# 误报边界

## B 端信息密度

高密度、较小行高、多字段搜索和复杂工作台不自动构成问题。只有当密度导致找不到、看不懂、比较困难、误操作或明显粗糙时上报。表格列数、字段数和菜单层级只作风险信号。

## 证据不足

代码或截图无法证明 hover、键盘、加载、接口错误、流程闭环和恢复行为时，不写确定问题；进入 `validation_backlog[]` 或 coverage 的 `not_tested / blocked`。

## 视觉偏好

“不够高级”“不够温暖”“颜色不好看”等无法落到层级、布局、间距、字体、对比、组件、状态或项目规范的个人偏好不报。页面粗糙、简陋和系统性不一致若有明确视觉证据，正常上报。

## 业务与项目约束

用户确认的业务规则、合规要求和 Design System 约束不得直接当作问题；检查其解释、呈现、防错、恢复和一致性。没有明确来源的像素、颜色、层级、列数和步骤阈值不得直接上报。

## PC 范围

移动端、小程序、App 和触屏任务不属于本 Skill 范围，不写 `not_tested`，也不输出移动端结论。PC 浏览器缩放、键盘、焦点和辅助技术仍须检查。
