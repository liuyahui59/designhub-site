# PC B 端体验走查报告模板

对话中输出完整 Markdown 报告，不只给摘要或文件链接。问题可以为零。

```markdown
# {项目名} — {完整 / 阶段性}体验走查报告

> 走查时间：{YYYY-MM-DD}
> 输入模式：{code / url / screenshot}
> 走查类型：{initial / follow_up}
> 报告状态：{complete / partial}
> 走查范围：{PC 页面与任务范围}

## 1. 走查前提

- 主要用户：{角色、职责、熟练度}
- 用户目标：{业务结果}
- 关键任务：{逐条列出任务 ID、名称、主要用户、起点与目标结果}
- PC 使用情境：{频率、屏幕、数据量、时间压力、中断/协作}
- 各任务成功标准：{在所属任务下逐条列出可观察标准}
- 失败影响与业务约束：{用户回答}

## 2. 范围与覆盖

- 页面视觉覆盖：{completed}/{total}
- 关键任务覆盖：{completed}/{total}
- 状态覆盖：{按任务列出状态清单完整性，以及各适用状态的通过、问题、未验证或阻塞摘要}
- 启用模块：{core / visual / accessibility-pc / ...}
- 页面清单完整性：{confirmed / partial}
- 完整性理由：{清单为何完整，或仍缺什么}
- 清单来源：{user_confirmed_scope / navigation_traversal / ...，附具体说明}
- 已知范围外页面：{页面、reason_code 与具体原因；无则写“无”}
- 主要 PC 环境：{viewport、窗口方式、浏览器缩放、证据与限制}
- 跨页面一致性：{completed / not_applicable / partial / blocked；比较页面、观察或未完成原因}

### 页面

| 页面 | 视觉状态 | 证据 |
|------|----------|------|

### 关键任务

| 任务 | 流程状态 | 状态覆盖摘要 | 证据 |
|------|----------|--------------|------|

## 3. 整体评价

{基于用户目标、任务轨与视觉轨给出综合判断。零问题时明确说明本次范围内未发现达到正式问题标准的确定缺陷。}

### 设计复查结论（仅 follow_up）

- 原报告：{标题与时间}
- 前提变化：{unchanged / changed；变化项}
- 复查范围：{targeted / full}

| 原问题 | 复查状态 | 验收标准结果 | 当前问题 | 结论 |
|--------|----------|--------------|----------|------|

回归检查：{passed / issues_found / partial；覆盖页面、任务、观察与证据}

## 4. 优先处理的问题

{只列确定问题，按严重度与任务/视觉影响排序。零问题时写“无”。}

## 5. 关键任务体验问题

### 1. [P1] {标题}

- 受影响用户：
- 关键任务 / 状态：
- 当前观察：
- 预期体验：
- 用户影响：
- 业务影响：{无可靠信息时省略}
- 影响依据：{expert_inference / observed_user_behavior / behavioral_data}
- 影响依据理由：{页面事实或实证如何支持该影响}
- 影响证据：
- 复现步骤：
- 严重度与置信度：
- 定级理由：
- 发生实例：{多页面、多任务或系统性问题逐项列出页面/任务、状态、观察与证据}
- 改进目标：
- 建议方向：
- 推荐理由：
- 约束与权衡：{P0/P1 或跨页面系统性问题必填；其他问题按需}
- 备选方向：{仅存在实质不同的合理方向时填写}
- 验收标准：
- 证据：

## 6. 页面视觉质量问题

{使用相同问题结构；关联页面，不强制关联任务。}

## 7. 跨页面系统性问题

{跨页面视觉系统或跨任务问题。}

## 8. 待验证风险

| 风险 | 潜在影响 | 验证优先级 | 验证方式 |
|------|----------|------------|----------|

## 9. 正向设计模式

{每项写明具体观察、用户价值、保留/复用指导，以及关联页面/任务、检查项和证据；无则写“无”。}

## 10. 可选增强机会

{每项写明当前状态、为什么不构成问题、预期价值、适用条件、设计方向和证据；不定 P 级；无则写“无”。}

## 11. 未覆盖范围与证据限制

{partial / blocked / missing 的页面、任务、状态和原因。}
```

建议质量统一按 `recommendation-quality.md` 执行，问题归并按 `issue-consolidation.md` 执行，正向模式与机会按 `positive-opportunity-method.md` 执行，设计复查按 `follow-up-review.md` 执行，影响结论按 `claim-evidence-boundary.md` 执行。不要输出单次走查的“Top 3 高频问题类型”。问题数量不代表优先级。不要推断开发成本、负责人、工期或上线版本。
