# 导航与信息架构设计

> 条件模块 `navigation-information-architecture`。触发：产品存在多个业务模块、对象层级、跨页面/跨模块关键任务，或详情内包含多种同级视图与子资源。单页工具、结构简单且不承担跨页面任务的页面不启用。

本模块评价用户如何理解系统结构、找到入口、确认位置并保持任务上下文。不审查路由代码、URL 组织、权限接口或菜单配置实现；只有它们造成入口不可理解、路径不一致、位置丢失或任务中断时，才形成体验问题。菜单项数量和层级深度只作风险信号，不设通用上限。

### NAV-01 业务心智模型与整体结构

检查模块、对象和任务的组织是否符合主要用户的业务概念、职责与工作顺序，而非按技术系统、数据库或内部组织架构机械划分。用户应能预测某项业务内容属于哪里；不要求所有角色共享完全相同的结构。

### NAV-02 全局、模块与对象内层级

检查全局导航、模块导航、页面级导航和对象内视图是否职责清楚、层级稳定。工作区切换、主菜单、页签、筛选和局部模式不应以相同视觉与交互方式混在一起，避免用户误判操作影响范围。

### NAV-03 命名、分组与顺序

检查菜单、页面标题、面包屑、入口和对象名称是否使用一致的用户业务语言；相近项是否能区分，分组与顺序是否支持高频任务和扫描。缩写、内部术语和同义词在造成理解成本时应统一或解释。

### NAV-04 当前位置与路径可理解

检查选中状态、页面标题、对象标识、面包屑和父子关系是否让用户知道“在哪里、正在处理什么、属于哪个范围”。从搜索、通知、收藏或深链接进入时，也应能理解当前位置和可返回路径。

### NAV-05 入口可发现与路径一致

检查关键任务入口是否出现在用户合理预期的位置，同类对象或操作入口是否跨页面一致。隐藏入口、仅 hover 出现的操作或多个不同名称的入口，只有实际降低发现性、增加绕路或造成误操作时才判问题。

### NAV-06 导航组件语义匹配

检查组件是否匹配关系类型：

- 菜单用于进入不同模块或页面。
- 面包屑表达层级路径，不替代流程步骤。
- Tab 用于同一对象或任务内的同级视图。
- 分段控制用于局部区域的互斥模式切换，不承担全局页面导航。
- 步骤条表达有顺序和完成关系的流程，不替代普通分类。
- Drawer、Modal 与独立页面应根据任务深度、上下文保留和影响范围选择。

组件名称本身不是结论，须验证用户是否能正确理解关系和操作后果。

### NAV-07 跨页任务与返回上下文

检查从列表、队列或仪表盘进入详情、编辑、审批和下钻后，返回时是否在任务需要时保留筛选、排序、分页、选中项、Tab、滚动位置和已完成进度。新开页、侧边面板或原页替换应匹配任务频率、比较需求和上下文价值。

### NAV-08 权限、动态入口与不可达状态

检查角色、对象状态或工作区变化后，入口的显示、隐藏、禁用和重定向是否可解释。用户能解决的权限或前置条件应给出原因和路径；不可执行操作不应留下误导入口，入口消失也不应让正在进行的任务无故失去方向。

## 与其他模块的边界

- 页面视觉层级、选中样式和导航组件完成度由 `visual` 负责。
- 任务入口、路径效率和返回上下文的通用要求由 `core` 负责；本模块补充复杂系统的结构与导航语义。
- 角色、状态和操作权限矩阵由 `object-lifecycle` 负责；本模块只检查权限变化如何影响导航理解。
- 键盘导航、焦点顺序和可访问名称由 `accessibility-pc` 负责。

同一观察可关联多个检查项，但只形成一个问题，避免重复统计。

## 完成标准

- 已枚举范围内的全局、模块、页面和对象内导航关系，以及关键任务的入口与返回路径。
- 已从主要入口、深链接/通知等适用入口和至少一条跨页任务验证当前位置与上下文保持。
- 每个 `NAV-*` 均有结构化 coverage；未验证的角色、入口或返回状态标为 `not_tested / blocked`，不得推断通过。
