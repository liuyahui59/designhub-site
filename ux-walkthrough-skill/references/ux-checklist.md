# PC B 端核心体验清单

> 所有任务强制启用。本文只保留跨产品稳定成立的核心原则；视觉质量和 PC 可访问性分别见 `visual-checklist.md`、`accessibility-pc.md`。

每项按 `verified_pass / issue / not_tested / not_applicable / blocked` 记录结构化 coverage。没有默认严重度；最终按 `severity-rubric.md` 结合用户、任务、频率、恢复和业务风险判断。

### CORE-01 用户目标与关键任务匹配

页面和流程是否支持 `review_brief` 中确认的用户目标；主信息和主操作是否服务于关键任务，而非仅展示已有功能。

### CORE-02 信息架构与路径

入口、当前位置、页面关系、返回路径和任务落点是否清楚；菜单层级与步骤数只作为风险信号，须验证实际查找、绕路和上下文损失。

### CORE-03 操作与信息可见性

主操作、行操作、隐藏操作、禁用原因、可滚动区域和状态变化是否可发现、可预期、可操作。

### CORE-04 进行中状态

加载、提交、上传、导入和长任务是否展示进行中、进度、可取消性，并防止无法解释的重复操作。

### CORE-05 结果反馈与任务闭环

成功、失败、部分成功和异步完成是否真实明确；结果是否落到列表、详情、状态、数量和下一步。

### CORE-06 防错、容错与恢复

是否预防高风险错误、保护用户输入、提供原因、修正、撤销或安全重试，并避免重复创建或提交。

### CORE-07 一致与可预测

术语、图标、功能色、组件行为、详情结构、保存落点、返回路径和状态变化是否跨页稳定。

### CORE-08 高频任务效率与上下文保持

是否减少重复录入、跳转、等待和人工核对；批量、快捷操作、筛选分页和返回上下文是否符合目标用户频率与熟练度。

### CORE-09 结果可信与数据透明

状态和反馈是否与真实结果一致；数据来源、更新时间、限制、不确定性和部分失败是否透明。

### CORE-10 内容、术语与帮助

文案是否使用业务语言，术语、日期、单位、空值和错误说明是否一致；复杂任务是否提供适量、场景化帮助，不机械要求所有流程都有引导。
