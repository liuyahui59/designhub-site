# 复杂表单与配置设计

> 条件模块 `form-configuration`。触发：关键任务包含创建、编辑、录入、设置或配置，并存在多组信息、字段依赖、重复项、多步骤、长页面、高风险配置或明显的专业控件选型需求。普通搜索框、单字段弹窗和简单确认不启用；不得用固定字段数量作为触发阈值。

本模块只评价用户能观察和操作的设计结果。接口字段、数据库结构、服务端校验、保存 API 和组件代码本身不作为体验问题；只有它们造成控件误用、理解困难、输入丢失、错误不可修正或状态不清时才形成结论。

### FORM-01 信息结构与填写顺序

检查字段分组、组名、顺序和渐进披露是否符合用户的业务判断与信息获取顺序。关联信息应靠近，低频高级设置不应干扰主要填写路径；不得仅因字段多就判定问题。

### FORM-02 标签、单位与填写语境

检查标签是否使用用户业务语言，必填/选填、单位、格式、取值范围、示例和后果是否在需要时可见。Placeholder 不代替标签，帮助说明应回答真实疑问而非重复字段名。

### FORM-03 控件与数据意图匹配

检查控件是否匹配数据类型、选项关系、精度、频率和操作后果：

- 安全且结果立即生效的二元状态可用开关；需要随整表提交或表达独立选择时用复选框。
- 少量互斥选项可用单选或分段控制；选项较多、需搜索或动态加载时用选择器或组合框。
- 数值根据精度与范围使用数值输入、步进器或滑杆；不得用普通文本框掩盖单位和格式。
- 日期、时间、人员、层级、颜色、文件等使用能表达对应数据结构的控件。
- 只读信息、禁用控件和不可编辑原因应可区分；可复制值不能被无故锁死。

组件库是否使用正确不是结论，用户能否理解、输入和确认结果才是判断依据。

### FORM-04 默认值、预填与录入效率

检查默认值、历史值、模板、继承、自动填充和批量录入是否减少重复劳动，同时不制造隐性选择。预填来源和适用范围在可能误用时应透明；高风险值不得仅凭惯性默认。

### FORM-05 字段依赖与动态变化

检查字段显隐、启用/禁用、选项更新、联动计算和条件分支是否可预测。上游值变化导致下游清空、失效或重算时，应及时说明并保护仍然有效的输入；隐藏字段不得造成不可见的提交后果。

### FORM-06 校验时机与错误修正

检查校验发生在合理时机，错误靠近对应字段并说明原因、要求和修正方式。提交后应能定位首个或全部错误；跨字段、分组和服务端错误应指向受影响信息，不以笼统失败提示代替。

### FORM-07 长表单、多步骤与定位

适用时检查目录、锚点、步骤、进度、已完成状态、返回修改和跨步依赖是否清楚。用户应知道当前位置、剩余工作和提交范围；拆步与否根据认知关系和业务顺序判断，不按字段数机械决定。

### FORM-08 编辑模式与未保存保护

检查查看/编辑边界、保存范围、即时生效与统一提交是否一致。取消、关闭、返回、切换对象或权限变化时，应明确处理未保存内容；草稿、自动保存、保存成功和保存失败的状态不能相互混淆。

## 与其他模块的边界

- 提交进行中、成功、失败与恢复由 `CORE-04 ... CORE-06` 负责，本模块只补充表单内部设计。
- 对象状态、角色权限、不可逆操作与下游同步由 `object-lifecycle` 负责。
- 字体、间距、对比度和组件视觉完成度由 `visual` 负责。
- 标签语义、键盘、焦点与错误可访问性由 `accessibility-pc` 负责。

同一观察可关联多个检查项，但只形成一个问题，避免重复统计。

## 完成标准

- 已识别关键表单的填写者、创建/编辑模式、保存方式和风险。
- 已实际覆盖默认、填写、联动、校验、取消/离开、保存成功与失败中的适用状态。
- 每个 `FORM-*` 均有结构化 coverage；静态截图无法证明的动态行为标为 `not_tested / blocked`，不得推断通过。
