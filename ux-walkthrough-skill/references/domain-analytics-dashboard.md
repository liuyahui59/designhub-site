# 仪表盘与数据可视化设计

> 条件模块 `analytics-dashboard`。触发：走查范围包含仪表盘、指标卡、趋势/比较/分布/构成图表，或关键任务要求用户监控、分析、比较、定位异常并下钻处理。仅展示少量辅助统计且不参与任务判断时，可不启用并说明理由。

本模块评价数据如何被解释和用于决策，不验证埋点实现、查询性能、统计代码、算法模型或数据仓库。只有数据定义或实现造成用户可观察的口径歧义、错误判断、状态不明或分析中断时，才形成体验问题。

### DASH-01 决策目标与信息优先级

检查指标、趋势、异常和明细是否支持 `review_brief` 中的用户目标与决策，而非堆叠可用数据。首要信息应对应最需要判断或处理的事项，装饰性指标不得挤占关键异常和行动入口。

### DASH-02 指标定义与统计语境

检查指标名称、定义、单位、统计范围、时间范围、时区、粒度和必要的数据来源是否足以正确理解。缩写、业务口径和派生指标在可能产生歧义时应可查；不得要求用户凭经验猜测分母或范围。

### DASH-03 比较基准与变化解释

检查当前值是否在任务需要时提供目标、阈值、上期、同期、基线或合理参照，并明确比较周期和方向。变化值应说明绝对值/百分比及正负含义；没有业务基准时不机械要求增加对比。

### DASH-04 图表类型与视觉编码

检查图表类型和位置、长度、面积、角度、颜色等编码是否匹配趋势、比较、分布、构成、关系或流程问题。多轴、堆叠、截断坐标、三维效果和过量颜色若可能造成误读，应有明确理由或改用更直接表达；不因某种图表类型本身直接判错。

### DASH-05 可读性与精确读取

检查标题、坐标轴、刻度、图例、标签、Tooltip、排序、单位和数值格式是否支持快速扫描与精确读取。任务需要核对具体值、长分类或多系列时，应提供适当的明细、表格或导出路径；不强迫所有概览图同时展示全部数字。

### DASH-06 筛选、联动与下钻上下文

检查时间、范围和维度筛选是否可见，作用域是否明确；图表联动、选择、高亮和下钻是否可发现且结果可解释。进入明细并返回后，应在任务需要时保留筛选、时间、选中项和滚动位置，避免失去分析上下文。

### DASH-07 数据新鲜度、完整性与可信度

检查更新时间、刷新状态、延迟、采样、估算、部分缺失和权限裁剪是否透明。不同模块口径或刷新时间不一致时，应防止被误当作可直接比较；过期或不完整数据不得呈现为无条件可信的当前结果。

### DASH-08 数据状态与行动闭环

检查加载、无数据、筛选无结果、部分加载、失败和无权限状态是否能区分，并说明数据是否安全、如何重试或调整条件。异常、预警和关键变化应在任务需要时提供可执行下钻或处理入口，而非停留在只读提示。

## 与其他模块的边界

- 页面层级、颜色、字体、图标和图表视觉完成度由 `visual` 负责。
- 数据反馈真实性、更新时间透明和任务闭环由 `core` 负责；本模块补充分析语境与可视化表达。
- 键盘、焦点、对比度、非颜色表达和图表可访问名称由 `accessibility-pc` 负责。
- 数据计算是否正确不是本 Skill 的开发审计内容；有可靠产品数据或规范证明页面展示错误时，才可作为确定问题。

同一观察可关联多个检查项，但只形成一个问题，避免重复统计。

## 完成标准

- 已识别每个主要指标或图表支持的用户判断、时间范围和数据范围。
- 已按适用情况验证筛选、比较、Tooltip、联动、下钻、返回、刷新、无数据、部分数据与失败状态。
- 每个 `DASH-*` 均有结构化 coverage；静态截图无法证明的交互和数据状态标为 `not_tested / blocked`，不得推断通过。
